# WSL2中的Shell 入门

## *What‘s the shell?*

计算机内用于工具之间**互相交互**的“工具”

## *What are the advantages of a shell?*

1.自动化几乎所有任务，以充分利用计算机的所有工具

2.几乎所有计算机平台都会用到shell，古老而又强大

3.你可以在几乎所有开源社区，开源项目里见到shell

*上古时期没有GUI*

### *What’s the way to open the shell?*

- Windows：按下 Win + R ，输入 `cmd` 或 `powershell` ，然后按下 Enter。
- Linux：Ctrl + Alt + T（适用于大多数发行版）。
- macOS：按下 ⌘ Cmd + Space 打开 「聚焦（Spotlight）」，输入「终端（Terminal）」，然后按下 Enter 。


*几乎所有的技术构建都会用到shell*

*在Windows上着会打开批处理（batch）或Poowershell，在LInux和macOS上通常会打开bash（Bourne Again Shell）

## 在shell中切换工作目录

```bash
pei15@HONORFuture:/mnt/c/Users/Pei15$ cd /
pei15@HONORFuture:/$ cd bin
pei15@HONORFuture:/bin$
pei15@HONORFuture:/bin$ cd ~
pei15@HONORFuture:~$
```

`cd`（change directory，切换目录），给它传入一个路径，该路径就会成为你的当前工作目录，提示符也会随之变化。

> `cd`实际上是 Shell 的内建命令，而不是独立程序（所以 `which cd` 会显示 `no cd found`）。
>
> `~`是 home 目录的简写，在 Linux 上通常对应 `/home/用户名`
>
> `$` 表示你当前不是 root 用户

如果不确定自己在哪个目录，可以运行 `pwd`（print working directory，打印当前工作目录），或者查看 `$PWD` 环境变量（如 `echo $PWD`）。两者都会输出当前路径。

```bash
pei15@HONORFuture:~$ pwd
/home/pei15
pei15@HONORFuture:~$ echo $PWD
/home/pei15
```

当前工作目录的另一重要作用是让我们能够使用**相对路径**。到目前为止我们看到的都是**绝对路径**：以 `/` 开头，给出了从文件系统根目录到目标位置的完整路径。 实际使用中，相对路径更常用。之所以叫「相对」，是因为它们是相对于当前工作目录来解析的。对于相对路径（即**任何不以 `/` 开头的路径**），Shell 会先在当前工作目录中查找路径的第一部分，然后逐级向下查找。

```bash
pei15@HONORFuture:~$ cd /
pei15@HONORFuture:/$ cd bin
pei15@HONORFuture:/bin$
pei15@HONORFuture:/bin$ cd /
pei15@HONORFuture:/$ cd bin/../bin/../bin/././../bin/..
pei15@HONORFuture:/$
```

>每个目录里还都有两个「特殊路径」：`.` 和 `..` 。
>
> `.` 表示「当前目录」，`..` 表示「父目录」。
>
>使用相对路径时，一定要清楚自己当前在哪个目录！

> 建议安装并使用 [`zoxide`](https://github.com/ajeetdsouza/zoxide) 来加速 `cd` 操作。它提供的 `z` 命令会记住你经常访问的路径，让你用更少的输入实现快速跳转。

## 查找Shell中可用的程序

当 Shell 需要执行命令时，它会查询 `$PATH` 环境变量。这个变量列出一组目录，Shell 会在这些目录中搜索与命令名匹配的程序：

```bash
pei15@HONORFuture:~$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/usr/lib/wsl/lib:/mnt/d/Program Files/STM32CubeCLT_1.21.0/st-arm-
......
pei15@HONORFuture:~$ which echo
/usr/bin/echo
pei15@HONORFuture:~$ /bin/echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/usr/lib/wsl/lib:/mnt/d/Program Files/STM32CubeCLT_1.21.0/st-arm-
......
pei15@HONORFuture:~$ $PATH
-bash: /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/usr/lib/wsl/lib:/mnt/d/Program: No such file or directory
```

运行 `echo` 时，Shell 识别出需要执行名为 `echo` 的程序，然后在 `$PATH` 中以冒号（`:`）分隔的目录列表里逐个搜索同名文件。找到后就运行它（**前提是该文件是可执行的**，这点稍后详述）。
可以用 `which` 查看某个命令实际对应哪个文件。也可以完全绕过 `$PATH`，**直接给出要执行文件的完整路径**。

> #### WSL2的文件目录的特点
>
> **双文件系统架构**‌：WSL2 内部默认使用 ext4 虚拟磁盘文件（`ext4.vhdx`）存储 Linux 原生文件，同时自动挂载所有 Windows 驱动器到 `/mnt` 目录下，实现双向文件互通。
>
> **跨系统访问路径**‌：在 Windows 资源管理器中可通过 `\\wsl$\<发行版名称>` 直接访问 WSL 的根目录内容。
>
> ‌**自动挂载机制**‌：Windows 的 C、D 等盘符会默认映射为 `/mnt/c`、`/mnt/d`，无需像原生 Linux 那样手动执行 mount 命令挂载外部存储。
>
> **性能分层特性**‌：WSL 原生 ext4 路径的 IO 性能是 `/mnt` 挂载 NTFS 路径的 3-5 倍，频繁读写的开发项目建议存放在 WSL 内部目录中。

可以把目录路径传给 `ls` 程序来实现（名称取自「list」，用于列出文件）列出 `$PATH` 中所有目录的内容这一功能，就能知道 Shell 中有哪些程序可用：

```bash
pei15@HONORFuture:~$ ls /bin

'['                                   lzmainfo

 aa-exec                              mailmail3

 ssh HONORFuture 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
```

我们只关注其中最重要的几个。先从简单的开始：

- `cat hello.txt`：打印 `hello.txt` 的全部内容
- `sort hello.txt`：将 `hello.txt` 的各行按字典序排序后输出
- `uniq hello.txt`：去除 `hello.txt` 中连续重复的行
- `head hello.txt` 和 `tail hello.txt`：分别打印 `hello.txt` 的前几行和后几行
- `grep pattern hello.txt`，它会在指定文本文件中查找所有匹配 `pattern` 的行。这个命令非常实用，值得多花些时间了解，它的功能比你想象的要丰富得多。

> 这里的 `pattern` 是**正则表达式（regular expression）**，可以描述非常复杂的匹配模式。

> 除了指定单个文件，你也可以指定一个目录作为搜索范围（或者直接不写，默认就是当前目录 `.` ），并加上 `-r` 参数让 `grep` 递归搜索目录里的所有文本文件，输出匹配的行。

`sed`，一个可编程的文件编辑器（stream editor）（流编辑器）。它有自己的「小语言」，可以自动化地修改文件。

```bash
pei15@HONORFuture:~$ sed -i 's/pattern/replacement/g' hello.txt
```

这条命令会把 `hello.txt` 中所有的 `pattern` 替换为 `replacement` 。具体来说：

- `-i` 参数表示直接修改文件（inline），而不是只在终端输出替换后的内容
- `s/` 是 `sed` 语法里表示「替换」（substitute）的意思
- 两个 `/` 用来分隔「匹配模式」和「替换内容」
- 结尾的 `/g` （global）表示在每一行中**替换所有匹配项**，而不仅仅是第一个

`find`，可以递归地查找满足特定条件的文件。

```bash
pei15@HONORFuture:~$ find ~/Downloads -type f -name "*.zip" -mtime +30
```

这会在下载（Downloads）目录中查找所有超过 30 天的 ZIP 文件。

```bash
pei15@HONORFuture:~$ find ~ -type f -size +100M -exec ls -lh {} \;
```

这会在 home 目录中查找所有大于 100M 的文件并列出它们。

> 注意，**`-exec` 接受一条命令**，命令以 `;` 结尾（因此需要像转义空格那样对它转义）。`find` 会把每个匹配文件的路径替换到 `{}` 的位置。

```bash
pei15@HONORFuture:~$ find . -name "*.py" -exec grep -l "TODO" {} \;
```

这会在当前工作目录下查找所有包含 TODO （这个大写单词）的 `.py` 文件。

> 建议安装并使用 [`fd`](https://github.com/sharkdp/fd) 来替代 find，它更加人性化（但可移植性稍弱）。

`awk` 则专门用来解析文件。 `awk` 最常见的用途是处理有规则格式的数据文件（比如 CSV），从每条记录（每一行）中提取你需要的部分

```bash
pei15@HONORFuture:~$ awk '{print $2}' hello.csv
```

这条命令会打印 `hello.csv` 中每一行的第二列（默认以空白字符分隔，空格或制表符都算）。如果你的文件是逗号分隔的（CSV 文件常见格式），可以加上 `-F,` 参数：

```bash
pei15@HONORFuture:~$ awk -F, '{print $2}' hello.csv
```

这样就会把每一行按逗号分成列，然后打印第二列。

> 除了提取列，`awk` 还能做很多事，如过滤行、计算统计、求和等。

## Shell——一门真正完整的语言

#### **管道（`|`）：**

它可以把一个程序的输出连接到另一个程序的输入。之所以可行，是因为多数命令行程序在未给出 `file` 参数时，会从「标准输入」（通常即键盘）读取数据。`|` 会把前面程序的「标准输出」（通常打印在终端上的内容）作为后面程序的标准输入。

> 借助这种机制，我们就能**把多个 Shell 程序组合（compose）起来**，这也是 Shell 如此高效的重要原因之一。

#### **重定向：**

**`> file`** 把程序的标准输出写入 `file` 而不是显示在终端，方便后续分析。

**`>> file`** 追加到 `file` 而不是覆盖。

**`< file`** 让程序从 `file` 读取输入而不是从键盘。

**`<> file`** 则是把两者结合，通知 Linux 内核：**“请为当前进程打开这个文件（或命名管道），并且同时赋予它读取和写入的绝对权限，不要清空文件内容。”**

**`<<<`（Here-String，单行文本流）**：这是极其高效的高阶符号，允许你把一个变量或字符串直接作为标准输入喂给某个命令。

```bash
echo "$var" | grep "Miku"
grep "Miku" <<< "$var"
#两者等价
```

#### **条件语句：**

**`if command1; then command2; command3; fi`**会先执行 `command1`，成功则继续执行 `command2` 和 `command3`。也可以加 `else` 分支。

**`while command1; do command2; command3; done`** 逻辑与前面的 `if` 类似，不同在于：只要 `command1` 不报错，就不断重复执行循环体。

**`for varname in a b c d; do command; done`** 会执行 `command` 四次，每次把 `$varname` 依次设为 `a`、`b`、`c`、`d`。

实际使用中，你往往不需要手动列出这些值，而是用「命令替换（command substitution）」。

```bash
for i in $(seq 1 10); do
```

这会执行 `seq 1 10`（输出 1 到 10 的所有整数），然后用该命令的输出替换整个 `$()`，得到一个循环 10 次的 `for` 循环。 在较早的代码中，你可能会看到用反引号（`for i in `seq 1 10`; do`）做同样的事；但现在应优先使用 `$()`，因为它支持嵌套。

> 虽然**可以直接在提示符里写很长的 Shell 脚本**，但通常更推荐把它们写进 `.sh` 文件。
>
> 最常作为 `command1` 的是 `test` 命令，通常简写为 `[`，可用于判断「文件是否存在」（`test -f file` / `[ -f file ]`）或「字符串是否相等」（`[ "$var" = "string" ]`）等条件。bash 还有 `[[ ]]`，是 test 的一种更安全的内置形式，在引号处理等方面的怪异行为更少。



> **`[]`与`test`**
>
> 1. *为什么 `[` 后面必须有空格，且结尾必须是 `]`？*
>
> 既然 `[` 是一个命令，那么根据 Shell 的语法规则，**命令与参数之间必须用空格隔开**。
>
> - **错误写法**：`[-d /tmp]` 或 `[ -d /tmp]` ── Shell 会报错 `[-d: command not found`，因为它把 `[-d` 当成了一个整体的命令名。
> - **正确写法**：`[ -d /tmp ]` ── 这里的 `[` 是命令，`-d` 是第一个参数，`/tmp` 是第二个参数，`]` 是第三个参数。
>
> **结尾的 `]` 有什么用？**
> 它没有任何实质性的条件判断功能，纯粹是 `[` 命令在代码设计上的**硬性强制要求**。`[` 命令在解析参数时，如果发现最后一个参数不是 `]`，就会直接抛出语法错误：`bash: [: missing ']'`。它的存在只是为了让代码看起来像传统编程语言的条件表达式。
>
> 所以，以下两条指令在底层执行时，传递给内核的参数和运行逻辑是**100% 相同**的：
>
> ```bash
> test -d /tmp
> [ -d /tmp ]
> ```
>
> 2. *`test` / `[` 的核心参数分类归纳*
>
> 它们通过不同的参数（选项）来对文件、字符串和数字进行三种维度的类型检查。
>
>  A. 文件状态测试（最常用）
>
> - `[ -d /tmp ]`：检查路径是否存在且是一个**目录**（Directory）。
> - `[ -f /tmp/file.txt ]`：检查路径是否存在且是一个**普通文件**（File）。
> - `[ -e /tmp/file.txt ]`：仅检查该路径**是否存在**（Exist），不管是文件还是目录。
> - `[ -s /tmp/file.txt ]`：检查文件是否存在且**大小大于 0 字节**（即文件非空）。
> - `[ -r/w/x file ]`：检查当前用户对该文件是否拥有**读/写/执行**权限。
>
>  B. 字符串测试
>
> - `[ -z "$str" ]`：检查字符串是否为**空**（Zero），长度为 0 时返回成功。
> - `[ -n "$str" ]`：检查字符串是否为**非空**（Not Zero），长度大于 0 时返回成功。
> - `[ "$str1" = "$str2" ]`：检查两个字符串是否**完全相等**。
>
>  C. 数值比较（只能比较整数）
>
> 注意：因为 `>` 和 `<` 在 Shell 里默认是重定向符号，所以 `test` 命令不使用它们进行数字比较，而是使用英文字母缩写：
>
> - `[ $num1 -eq $num2 ]`：是否**相等**（Equal）
> - `[ $num1 -ne $num2 ]`：是否**不相等**（Not Equal）
> - `[ $num1 -gt $num2 ]`：是否**大于**（Greater Than）
> - `[ $num1 -ge $num2 ]`：是否**大于等于**（Greater Equal）
> - `[ $num1 -lt $num2 ]`：是否**小于**（Less Than）
> - `[ $num1 -le $num2 ]`：是否**小于等于**（Less Equal）
>
> 3. *为什么现代脚本更推荐升级版的 `[[ ]]`？*
>
> 虽然 `[` 很经典，但在编写高难度脚本时，建议使用 Bash 特有的升级版双中括号 **`[[ ... ]]`**（关键字扩展语法）。
>
> 1. **不再需要防空变量引用**：
>    如果变量 `$var` 为空，写 `[ $var = "Miku" ]` 会直接报语法错误，因为变量展开后命令变成了 `[ = "Miku" ]`。你必须极其痛苦地加双引号写成 `[ "$var" = "Miku" ]`。
>    而使用双中括号 `[[ $var = "Miku" ]]`，即使变量为空也能安全执行。
>
> 2. **原生支持逻辑运算符**：
>    在 `[` 中做“且”和“或”组合，必须使用晦涩的 `-a` 和 `-o` 参数。
>    而在 `[[ ]]` 中，你可以直接使用标准的 **`&&`** 和 **`||`** 符号：
>
>    ```bash
>    [[ -d /tmp && -w /tmp ]]
>    ```
>
> 3. **原生支持 Glob 模糊匹配和正则表达式**：
>    `[[ "hello.txt" == *.txt ]]` 可以直接利用前面学过的 **Glob** 机制进行文件名匹配。

## 例题

1.下面这个脚本会在循环中不断运行某个程序直到它失败；它只打印失败那次的输出，同时在后台对 CPU 施加压力（这在复现偶尔失败的测试（flaky test）时非常有用）。

``` bash
#!/bin/bash
set -euo pipefail

# Start CPU stress in background
stress --cpu 8 &
STRESS_PID=$!

# Setup log file
LOGFILE="test_runs_$(date +%s).log"
echo "Logging to $LOGFILE"

# Run tests until one fails
RUN=1
```

2.`ls` 的 `-l` 选项（flag）作用是什么？运行 `ls -l /` 并观察输出。每一行最前面的 10 个字符分别代表什么？（提示：`man ls`）

`ls` 命令的 **`-l` 选项** 作用是使用**长列表格式（Long Listing Format）**列出文件和目录的详细信息。

第 1 个字符：文件类型 (File Type)，代表该项是什么类型的特殊文件：

- **`-`**：普通文件（Regular file）

- **`d`**：目录（Directory）

- **`l`**：符号链接/软链接（Symbolic link）

- `c` / `b` / `s` / `p`：分别代表字符设备、块设备、套接字或命名管道。

  > 在 `/` 根目录下，你最常看到的是 `d` 和 `l`。

后 9 个字符：三组权限设置 (Permissions)，剩下的 9 个字符分为 **3 组**，每组 3 个字符，分别对应不同的用户身份。每组内部的权限字母为 `r`（可读）、`w`（可写）、`x`（可执行），若无该权限则显示为 `-`：

- **第 2、3、4 个字符**：**所有者权限（User/Owner）**
  - 控制该文件创建者或当前归属所有者的读、写、执行权限。
- **第 5、6、7 个字符**：**所属用户组权限（Group）**
  - 控制与该文件属于同一用户组的其他成员的读、写、执行权限。
- **第 8、9、10 个字符**：**其他人权限（Others）**
  - 控制系统内除所有者和组内成员之外，所有其他用户的读、写、执行权限。

> 在 Linux 内部，每个文件都有一个唯一的**“身份证号”（称为 Inode，索引节点）**，里面记录着文件的权限、大小和数据真正存放的磁盘位置。它们的核心区别如下：
>
> #### *硬链接 (Hard Link) —— 同一个文件的不同名字*
>
> - **底层原理**：硬链接是指向**同一个 Inode 号码**的多个文件名。它们共享同一块磁盘数据。
> - **特点**：
>   - 每一个硬链接都是一个对等的“正牌”文件名。
>   - **删不干：** 删掉其中一个文件名，只要硬链接数不为 0，文件数据就依然存在。
>   - **不占空间：** 无论建多少个硬链接，都不额外占用磁盘空间（不复制数据）。
>   - **局限：** 不能跨文件系统（跨分区），且不能针对**目录**创建硬链接。
> - **命令**：`ln 源文件 硬链接名`
>
> #### *软链接 / 符号链接 (Symbolic Link / Soft Link) —— 快捷方式*
>
> - **底层原理**：软链接是一个**独立的新文件**，它有自己**全新的 Inode 号码**，而它的文件内容里只带有一串文本——**“源文件的路径字符串”**。
> - **特点**：
>   - **会失效：** 如果源文件被删除了，软链接就会指向一个空地址，变成死链接（闪烁红字报错）。
>   - **极其灵活：** 可以跨越不同的磁盘分区，也可以随心所欲地为**目录**创建快捷方式（你在之前输出里看到的 `bin -> usr/bin` 就是典型的目录软链接）。
> - **命令**：`ln -s 源文件 软链接名`（必须带 `-s` 选项）

3.在命令 `find ~/Downloads -type f -name "*.zip" -mtime +30` 中，`*.zip` 是一个 「glob」。什么是 glob ？新建一个测试目录并创建一些文件，试试 `ls *.txt` 、`ls file?.txt` 、`ls {a,b,c}.txt` 等模式。 [Pattern Matching](https://www.gnu.org/software/bash/manual/html_node/Pattern-Matching.html) 。

**Glob（全称 Globbing）是 Shell 用于路径名扩展（Pathname Expansion）的通配符匹配机制。**

根据 GNU Bash 手册的模式匹配说明，Glob 与正则表达式不同，它由 Shell 在执行命令前**直接解析并展开**为具体的文件名列表。

#### `ls *.txt` —— 星号通配符

- **规则**：`*` 匹配**任意数量**（包括零个）的任意字符。
- **预期输出**：`a.txt` `b.txt` `c.txt` `d.txt` `file1.txt` `file2.txt` `fileA.txt` `file10.txt`
- **原理解析**：它揪出了当前目录下所有以 `.txt` 结尾的文件，无论名字多长。

#### `ls file?.txt` —— 问号通配符

- **规则**：`?` 严格匹配**有且仅有一个**任意字符。
- **预期输出**：`file1.txt` `file2.txt` `fileA.txt`
- **原理解析**：`file10.txt` 不会被匹配，因为 `10` 占据了两个字符位置；同时 `a.txt` 也落选，因为它前面缺了 `file`。

#### `ls {a,b,c}.txt` —— 大括号扩展 (Brace Expansion)

- **规则**：`{}` 严格来说属于大括号扩展。Shell 会把命令硬性拆解为 `ls a.txt b.txt c.txt` 并依次去寻找它们。
- **预期输出**：`a.txt` `b.txt` `c.txt`
- **原理解析**：即使这三个文件在磁盘上不存在，Shell 在初始展开阶段也会强行生成这个列表，这与 `*` 或 `?` 必须匹配磁盘上现存文件的机制不同。

#### 进阶模式：`ls file[0-9].txt` —— 字符集匹配

- **规则**：`[...]` 匹配方括号内包含的**任意一个**字符。`0-9` 表示数字范围。
- **预期输出**：`file1.txt` `file2.txt`
- **原理解析**：它成功过滤掉了带字母的 `fileA.txt`。

4.`'单引号'`、`"双引号"` 和 `$'ANSI 引号'` 有什么区别？写一条命令，输出一个同时包含字面量 `$` 、`!` 和换行符的字符串。参见 [Quoting](https://www.gnu.org/software/bash/manual/html_node/Quoting.html) 。

- **`'单引号'`（强引用）**：**保持一切字符的字面本意**。在单引号内，变量（`$VAR`）、反斜杠（`\`）以及任何特殊符号都会失去魔力，变成纯文本。单引号内绝不能再直接出现单引号。
- **`"双引号"`（弱引用）**：**允许变量扩展和命令替换**。它会保留绝大多数文本，但以下字符依然会被 Shell 解析：美元符号（`$`，用于读取变量）、反撇号（ ```，用于命令替换）、反斜杠（`\`，仅在后跟 `$`, ```, `"`, `\`, 或换行符时起转义作用）。此外，由于 Bash 的历史扩展机制，双引号内的惊叹号（`!`）常被误解析为历史命令，需格外注意。
- **`$'ANSI 引号'`（转义强引用）**：**专门用于解析 ANSI 系统的 C 语言风格转义字符**（如 `\n` 代表换行，`\t` 代表制表符）。它会把这些反斜杠开头的组合直接替换为对应的不可见控制字符。

> 在双引号之前加美元符号（即 **`$"..."`**），**在 Bash 中触发的是本地化翻译（Locale-Specific Translation）机制**。
>
> 在实际编写脚本时，**强烈建议不要使用 `$"..."`**。因为恶意翻译文件可能会在译文中注入危险的变量或命令替换（如 `$(rm -rf /)`），导致脚本在执行翻译文本时触发严重的安全漏洞。现代自动化运维更倾向于直接使用标准的 `gettext` 工具来实现多语言。

```bash
pei15@HONORFuture:~$ echo $'Hello $\nWorld !'
Hello $
World !
```

> `\n`：被 `$'...'` 成功识别并替换成了真正的物理换行。
>
> `$` 与 `!`：由于 `$'...'` 的安全机制，它们不会触发变量查找或历史命令扩展，被安全地当作纯文本字面量输出。

5.Shell 有三条标准流：stdin（0）、stdout（1）、stderr（2）。运行 `ls /nonexistent /tmp` ，把 stdout 和 stderr 分别重定向到两个文件。你将如何把两者都重定向到同一个文件？参见 [Redirections](https://www.gnu.org/software/bash/manual/html_node/Redirections.html) 。

#### 三条标准流的本质

在 Linux 中，“一切皆文件”。程序启动时，系统会自动为其打开三个虚拟的“数据通道”：

- **`stdin`（标准输入，文件描述符 0）**：程序**读取**数据的地方。默认连接到你的键盘。
- **`stdout`（标准输出，文件描述符 1）**：程序输出**正常执行结果**的地方。默认连接到你的屏幕。
- **`stderr`（标准错误，文件描述符 2）**：程序输出**报错、异常信息**的地方。默认同样连接到屏幕。
  - *设计成两个流的原因*：即使正常输出被存成了文件，报错信息依然能在屏幕上弹出，不会被掩盖。

#### **指令一：分别重定向**

```bash
ls /nonexistent /tmp > stdout.log 2> stderr.log
```

- `ls` 命令由于找不到 `/nonexistent`，会向 **`2` (stderr)** 发送报错；由于成功找到了 `/tmp`，会向 **`1` (stdout)** 发送列表结果。
- `> stdout.log`：这是 `1> stdout.log` 的简写。它强行截断了 **`1` 通道**，把本该去屏幕的正常结果倒进 `stdout.log`。
- `2> stderr.log`：它强行截断了 **`2` 通道**，把本该去屏幕的报错信息倒进 `stderr.log`。
- **结果**：屏幕上一片安静。两个文件各自精准地拿到了属于自己的数据。

#### **指令二：合并重定向到同一个文件**

```bash
ls /nonexistent /tmp > output.log 2>&1
```

这条指令的执行顺序是**从左到右**的：

1. **`> output.log`**：先把 **`1` (stdout)** 指向 `output.log` 文件。
2. **`2>&1`**：把 **`2` (stderr)** 指向 **“当前 `1` 所指向的地方”**。因为此时 `1` 已经指向了文件，所以 `2` 也就跟着指向了文件。

- **结果**：无论是正常结果还是报错，统统顺着各自的通道，最终汇聚到了同一个 `output.log` 文件中。

> `exec` 是什么指令？
>
> 在 Bash 中，`exec` 是一个非常特殊的**内置命令（Built-in）**。它有两种完全不同的核心用法：
>
> 用法 A：替换当前进程（Process Replacement）
>
> 当你在终端运行 `exec top` 时，`top` 命令不会像普通命令那样去创建（fork）一个子进程，而是**直接吃掉并强行占领当前正在运行的 Shell 进程**。
>
> - **后果**：由于原来的 Shell 进程在内存中被彻底抹去了，一旦 `top` 退出，整个终端窗口或 SSH 连接会**直接关闭**，无法返回原先的命令行。
>
> 用法 B：永久重定向操作流（Stream Redirection）
>
> 当 `exec` 后面跟的是**重定向符号**（如 `>`, `<`）而不是具体的命令时，它**不会**替换进程。相反，它会**强行修改当前整个 Shell 进程的默认文件描述符映射**。
>
> - 通常的重定向（如 `echo "hello" > log`）只对那**一条命令**单次生效；
> - 而使用 `exec > log` 之后，**接下来脚本里的每一行命令**都会默认把输出写入到 `log` 文件中，直到脚本结束。

> `exec 3>&1 1>>logfile 2>&3` 乾坤大挪移
>
> 在 Linux 中，文件描述符不仅有 `0, 1, 2`。你还可以自定义并使用 `3` 到 `9` 的数字。这一行神仙代码常用于高级日志框架，作用是：**把标准输出保存到日志，同时把报错信息强行剥离出来，打印到屏幕上。**
>
> 为了看懂这个“乾坤大挪移”，我们必须引入一个临时变量（就像交换 A 和 B 的值需要临时变量 C 一样）：
>
> 1. **`3>&1`**：创建一个全新的通道 `3`，并让它指向**当前 `1`（即屏幕）**。此时，通道 `3` 成为了屏幕的备份。
> 2. **`1>>logfile`**：把通道 `1` 重定向到日志文件（以追加模式 `>>`）。此时正常输出开始流入文件。
> 3. **`2>&3`**：把通道 `2` 指向**通道 `3` 所指向的地方（即最初的屏幕）**。
>
> **最终神奇的效果**：程序所有的正常输出（`stdout`）都悄悄进去了日志文件，而所有的报错信息（`stderr`）非但没有进文件，反而借由通道 `3` 的跳板，精准地砸在了你的屏幕上！

>Bash 专属的高级简写：`&>`
>
>如果你使用的是 Bash 4.0+（现代 Linux 默认都是），每次写 `> file 2>&1` 难免觉得冗长。Bash 专门提供了一个终极简写：
>
>```bash
>ls /nonexistent /tmp &> output.log
>```
>
>这里的 `&>` 是一个整体符号，意思是**“把所有流（无论是 1 还是 2）一股脑全倒进后面这个文件”**。它在底层等价于 `> file 2>&1`，不仅少敲了字符，而且彻底避免了因为顺序写错而导致的 Bug。

6.`$?` 保存上一条命令的退出状态。 `&&` 仅在前一条成功时执行后一条；`||` 仅在前一条失败时执行后一条。写一个一行命令：仅当 `/tmp/mydir` 不存在时才创建它。参见 [Exit Status](https://www.gnu.org/software/bash/manual/html_node/Exit-Status.html) 。

>在 Linux Shell 中，**`0` 表示成功（Success），而非 `0` 的所有正整数（如 `1`、`2`、`127` 等）都表示失败（Failure）。**

```bash
[ -d /tmp/mydir ] || mkdir /tmp/mydir
```

核心逻辑拆解

- **`[ -d /tmp/mydir ]`**：利用 `[` 命令检查 `/tmp/mydir` 是否存在且为一个**目录**。
  - 如果目录**存在**，命令执行成功，`$?` 返回 `0`。
  - 如果目录**不存在**，命令执行失败，`$?` 返回 `1`。
- **`||`（短路或）**：根据它的特性，只有当前面的命令**失败（**`$?` **不为 0）**时，才会触发执行后面的命令。
- **最终效果**：只有当目录不存在（前面返回 1）时，后面的 `mkdir /tmp/mydir` 才会安全执行。

7.为什么 `cd` 必须是 Shell 内建命令，而不能是独立程序？（提示：想想子进程能影响和不能影响父进程的哪些状态）

1. ***独立程序的致命局限：子进程隔离***

在 Linux 系统中，如果一个命令是独立程序（比如 `ls`、`mkdir`，它们在 `/bin/` 目录下有真实的二进制文件）：

1. 当前的 Shell 必须通过 `fork()` 创建一个**子进程**来运行这个程序。
2. 子进程会全盘复制父进程的状态，拥有自己独立的内存空间和运行上下文。

如果 `cd` 是一个独立程序（假设路径为 `/bin/cd`），当你运行 `cd /tmp` 时：

- 系统会启动一个进程号为（例如）`9999` 的子进程。
- 这个子进程在自己的空间里非常听话地把目录切换到了 `/tmp`。
- **致命问题**：当子进程执行完毕并退出后，它所做的一切改变都会随着进程的销毁而烟消云散。作为父进程的 Shell，其工作目录**依然停留在原地，毫无变化**。

------

2. ***内建命令可在父进程内部直接修改***

为了让工作目录真正发生改变，`cd` 必须在**当前 Shell 进程内部**直接执行，而不能派生子进程。

当 `cd` 被设计为内建命令时：

- Shell 看到 `cd` 后，不会去调用 `fork()`。
- 它会直接在当前的进程上下文里，调用 Linux 的系统调用（System Call）——`chdir("/tmp")`。
- 这样，**当前 Shell 进程自身**的工作目录就直接被修改了，接下来的所有命令（如 `ls`）也就能在正确的新目录下运行。

>在 Linux 的进程树中，状态的继承和传递是**单向**的。
>
>- **子进程完全不能影响父进程的**：
>  - **工作目录**：如上所述。
>  - **环境变量**：你在子进程里 `export A=1`，父进程里找不到 `$A`。
>  - **内存变量**：子进程修改变量值，父进程无感。
>  - **文件描述符的关闭**：子进程关闭自己的 `0,1,2`，父进程的通道依旧完好。
>- **子进程可以影响父进程的**：
>  - **退出状态码（`$?`）**：子进程退出时，通过 `exit(code)` 向父进程汇报自己的死因，这是唯一的标准反馈通道。

>在 Linux 系统中，你敲下的每一条命令，本质上可以分为三大类：**内建命令（Shell Built-ins）**、**外部命令（External Commands）** 和 **别名/函数（Aliases/Functions）**。
>
>其中，**内建命令**与**外部命令**构成了 Linux 执行引擎的核心对立面。它们在底层的执行机制、系统开销以及对环境的影响上有着本质的区别。
>
>1. 核心底层区别对照表
>
>| 特征维度         | 内建命令 (Built-ins)                        | 外部命令 (External)                            |
>| ---------------- | ------------------------------------------- | ---------------------------------------------- |
>| **代表命令**     | `cd`, `exit`, `echo`, `read`, `pwd`         | `ls`, `grep`, `awk`, `g++`, `docker`           |
>| **真实身份**     | Shell 源代码里的**一段 C 语言函数**         | 硬盘上某个目录下的**独立二进制文件**           |
>| **执行方式**     | 由当前 Shell 进程**直接调用函数**执行       | 必须 `fork()` 创建**子进程**，再 `exec()` 加载 |
>| **性能开销**     | **几乎为零**。无需创建进程，速度极快        | **较高**。高并发下频繁创建进程会导致系统变慢   |
>| **环境变量修改** | **可以**永久修改当前 Shell 的环境变量和目录 | **绝不可能**修改当前 Shell 的任何状态          |
>| **寻找路径**     | 直接在内存中识别                            | 必须扫描环境变量 `$PATH` 里的目录去挨个找      |
>
>2. 运行机制剖析
>
>当输入 `exit` 或 `cd /tmp` 时：
>
>1. 当前的 Shell 进程（例如 Bash）直接匹配到了这个关键字。
>2. Bash **不离开自己的进程空间**，直接跳转到其源码内部对应的 `builtin_cd()` 内部 C 函数。
>3. 它在当前进程中调用内核系统调用更改自身状态，执行完后直接返回命令行。整个过程没有产生任何新的进程 ID（PID）。
>
>当输入 `g++ main.cpp` 时：
>
>1. Bash 无法在内存中直接认出它，于是开始疯狂扫描你的 `$PATH` 变量（去 `/usr/bin`, `/bin` 等目录翻找名为 `g++` 的可执行文件）。
>2. 找到后，Bash 调用系统底层的 `fork()` 派生出一个崭新的**子进程**。
>3. 该子进程随即调用 `execve()`，把硬盘上的 `g++` 二进制代码强行加载覆盖到自己的内存中，变成一个独立的评测任务进程。
>4. 运行结束后，子进程销毁，并通过 `exit(code)` 把死因（状态码）丢回给父进程（Bash）。
>
>***可以使用内置的 `type` 命令来对命令进行"身份审查”***

> #### ***关于LinuxShell中的`-`***
>
>  **`-`** 
>
> 1. **本质**：它不是参数，也不是选项，它是标准输入（stdin）或标准输出（stdout）的**虚拟文件名**。
> 2. **白话**：“请不要去硬盘找文件，直接从**键盘或管道**里读写数据。”
> 3. **实战**：`cat -`（从键盘读什么就印什么）或 `bash -`（直接执行从管道传过来的网络代码）。
>
>  **`--`** 
>
> - **本质**：纯粹的**语法控制符**。它的唯一作用是**强行关闭命令的参数解析引擎** [I]。
> - **白话**：“到此为止！后面不管是啥（哪怕长着负号 `-`），全给我当成**普通的文件名或文本**！”
> - **实战**：`rm -- -rf`（安全删除一个名字叫 `-rf` 的奇葩文件，绝不误删系统） [I]。
>
>  **`- --`** 
>
> - **本质**：由于中间有**空格**，它代表连续传给命令的两个独立参数。
> - **白话**：“先帮我处理**标准输入流（`-`）**，然后顺便**关闭（**`--`）接下来的选项解析。”
>
> - *(注：在一些复杂的级联过滤中，也会写成 `-- -`，即关闭解析，再把后面的 `-` 安全地降维识别为标准输入流。)*
>
>  **`--help`** 
>
> - **本质**：以**双横线开头**的现代 GNU 参数规范，后面跟一个完整的单词。
> - **白话**：“我是现代标准的帮助选项，请打印官方使用手册，不要把我拆开。”
> - **实战**：`ls --help`，它绝对不会被拆成 `-h -e -l -p`，而是直接触发整个帮助界面。
>
> **`-help`** 
>
> - **本质**：以**单横线开头**的老 UNIX 参数规范。
> - **白话**：“如果命令很古老，它会把我强行拆解成 **`-h`、`-e`、`-l`、`-p`** 四个独立的单字母快捷键。”
> - **特例**：现代只有极少数命令（如特立独行的 `find -help`）在内部做了硬编码兼容，绝大多数命令输入 `-help` 都会因为不认识其中的某个字母（如没有 `-p` 选项）而直接报错崩溃。

8.写一个脚本，接收文件名参数（`$1`），用 `test -f` 或 `[ -f ... ]` 检查该文件是否存在，并根据结果输出不同提示。参见 [Bash Conditional Expressions](https://www.gnu.org/software/bash/manual/html_node/Bash-Conditional-Expressions.html) 。

```bash
#!/bin/bash
# 启用安全模式：遇到未定义变量或管道错误立即退出
set -euo pipefail

# 1. 变量防空：检查用户是否忘记输入文件名参数
# -z 检查字符串是否为空。如果 $1 为空，则打印错误提示并以状态码 1 退出
if [ -z "${1:-}" ]; then
    echo "❌ 错误: 请提供文件名参数！" >&2
    echo "用法: $0 <文件名>" >&2
    exit 1
fi

# 将第一个参数存入易读的变量中
TARGET_FILE="$1"

echo "🔍 正在检查目标: $TARGET_FILE ..."

# 2. 核心逻辑：使用 [ -f ... ] 结合 -- 安全防御进行条件测试
# -- 确保即使文件名叫 "-help" 或 "-rf"，也不会误触发 [ 命令的内部选项
if [[ -f "$TARGET_FILE" ]]; then
    echo "✅ 提示: 普通文件 [ $TARGET_FILE ] 存在，且可以正常访问。"
else
    # 3. 进阶容错：如果不是普通文件，进一步细分原因
    if [[ -d "$TARGET_FILE" ]]; then
        echo "⚠️  提示: 路径 [ $TARGET_FILE ] 存在，但它是一个【目录】，不是普通文件！"
    else
        echo "❌ 提示: 文件 [ $TARGET_FILE ] 不存在，或当前用户无权访问。"
    fi
fi
```

1. **`${1:-}` 变量防空陷阱**：
   因为脚本开头开启了 `set -u`（遇到未定义变量立刻报错退出）。如果用户直接运行脚本而不传参数，直接写 `$1` 会触发 Bash 报错强制退场。这里使用 `${1:-}` 语法，意思是“如果 `$1` 没传，就默认当成空字符串处理”，从而让接下来的 `[ -z ... ]` 能够安全拦截并打印出人性的用法提示。

   >`${1:-}` 里的 `-` 是一个**“默认值赋权运算符”**（Default Value Operator）
   >
   >它的核心语法结构是 `${变量:-默认值}` [1]。在当前场景下，因为 `-` 后面什么都没有写，所以它的含义是：**“如果 `$1` 没传（未定义）或者为空，就默认把它当成【空字符串】处理”**。

2. **`[ -f ... ]` 传统单中括号的致命防翻车漏洞**：
   在项目中，用户随时可能提交一个名字怪异的代码文件（恶意命名为 `-d` 或 `-f`等）。

   1. **为什么不能用 `--`？**
      传统的 `[` 或 `test` 命令**完全不支持**通过加入 `--` 来终止参数解析。如果你写成 `[ -f -- "$TARGET_FILE" ]`，`[` 命令内部死板的 POSIX 解析器会把 `--` 误认为是一个非法的二元操作符，直接抛出 `binary operator expected` 语法崩溃。 [[1](https://ayedaemon.medium.com/bare-double-dash-in-commands-a3685c9a6403), [2](https://medium.com/fhinkel/the-curious-case-of-double-dashes-b5e7711698f)]

   2. **老派 `[` 的唯一正确防御手法：【路径前缀法】**
      如果你必须在老派的 `[` 中防御长得像选项的文件（如 `-file.cpp`），老练的系统管理员会通过**强行挂载路径前缀 `./`** 来破除 Flag 魔法：

      ```bash
      if [ -f "./$TARGET_FILE" ]; then
      ```

      即使变量内容是 `-file.cpp`，拼接后也会变成 `./-file.cpp`。由于字符串不再以 `-` 开头，`[` 命令就能安全、精准地把它当作普通文件名去硬盘查找了。

   3. **现代最佳实践：彻底抛弃 `[`，升级为 `[[ ... ]]`**
      最完美的闭环防御是不使用 `[`，直接升级为 Bash 现代双中括号 `[[ -f "$TARGET_FILE" ]]`。`[[ ]]` 是 Bash 的内置关键字，它在内核层对变量进行了强力的类型保护，**天生免疫一切长得像 Flag 的文件名，且不需要加任何 `--` 或 `./` 前缀**。

   >**双中括号 `[[ ... ]]`** 在 Bash 中被称作**扩展测试关键字（Extended Test Keyword）**。它之所以能在底层完美解决单中括号 `[` 的各种诡异报错和文件名冲突，是因为它**不再是一个普通的命令，而是直接成为了 Bash 解释器的一部分（关键字语法）**。
   >
   >它的核心运行逻辑和底层运作机制主要体现在以下四个核心维度：
   >
   >1. 延迟解析与“双引号免疫”逻辑
   >
   >- **单中括号 `[` 的逻辑**：Shell 会先做**变量替换**（把 `$var` 展开），然后再把这一堆零散的字符串当成参数传给 `[`。如果变量为空，参数直接在原地消失；如果变量带空格，一个参数会被切成两个参数，从而引发 `too many arguments`。
   >- **双中括号 `[[ ]]` 的逻辑**：Bash 遇到 `[[` 后，会**立刻开启“特殊保护视窗”**。它会把 `[[ ... ]]` 内部的整串表达式当作一个有结构的**语法树（AST）**来解析。在变量被真正展开前，Bash 就已经明确知道了这里是一个条件对比。因此：
   >  - 即使 `$TARGET_FILE` 变量为空，Bash 也会在内部安全地用空字符串替换，**绝对不报语法错误**。
   >  - 即使文件名包含空格、甚至名字叫 `-d`，Bash 也会通过语法树将其强行锚定在“对比值”的位置上，**天生免疫任何 Flag 选项冲突**，不需要加任何 `--` 或 `./` 前缀。
   >
   >------
   >
   >2. 逻辑运算符的“短路机制”直接介入
   >
   >在单中括号 `[` 中，如果你想做“既满足 A 又满足 B”的判断，必须使用 `-a`（And）参数：
   >
   >```bash
   >[ -d /tmp -a -w /tmp ]
   >```
   >
   >但在底层，`-a` 是作为 `[` 命令的参数传入的，它无法控制 Shell 的执行流。
   >
   >在双中括号 `[[ ]]` 中，你可以直接使用 Bash 原生的 **`&&` 和 `||`** 短路运算符 [I]：
   >
   >```bash
   >[[ -d /tmp && -w /tmp ]]
   >```
   >
   >- **底层逻辑**：由于 `[[` 是内置关键字，这里的 `&&` 触发的是真正的**内核级短路求值（Short-circuit evaluation）**。如果左边的 `-d /tmp` 失败了，右边的 `-w /tmp` 连看都不会看一眼，直接跳过。这不仅性能极高，而且在写高并发运维脚本时极具鲁棒性。
   >
   >------
   >
   >3. 右侧参数的模式匹配逻辑
   >
   >双中括号的右侧如果是一个不加双引号的字符串，它的匹配逻辑会发生降维打击。它支持两种单中括号想都不敢想的高级操作：
   >
   >逻辑 A：Glob 通配符匹配
   >
   >```bash
   >if [[ "$FILENAME" == *.cpp ]]; then
   >```
   >
   >请谨慎使用此类代码。
   >
   >- **运行逻辑**：当右侧的 `*.cpp` 没有被双引号包裹时，`[[ ]]` 内部会调用 Bash 自带的 **Glob（通配符）引擎** [II]。它会自动去匹配变量是否以 `.cpp` 结尾。如果换成单中括号 `[`，系统会误认为你想在当前目录下翻找现存的文件，直接报错。
   >
   > 逻辑 B：原生正则表达式匹配（`=~`）
   >
   >```bash
   >if [[ "$USER_INPUT" =~ ^[0-9]+$ ]]; then
   >```
   >
   >请谨慎使用此类代码。
   >
   >- **运行逻辑**：当你使用 `=~` 运算符时，`[[ ]]` 会直接启动系统的 **POSIX 扩展正则表达式（ERE）引擎**。它会在不启动任何外部 `sed` 或 `awk` 进程的情况下，纯在当前 Shell 的内存里一瞬间完成高难度的正则校验。
   >
   >------
   >
   >4. 终极性能优化：零外部调用，纯内存操作
   >
   >- 运行外部命令或早期 UNIX 的 `[` 时，系统即便不 `fork` 也要在命令表里做一次检索。
   >- 而 `[[ ... ]]` 的所有运算——包括文件类型测试、字符串对比、正则和通配符匹配——**全部是在当前 Shell 进程的局部内存空间内以 C 语言原生速度执行的**。

   >核心底层区别对照表
   >
   >| 特征维度        | 内置关键字 (Reserved Keywords)           | 内建命令 (Shell Built-ins)                   |
   >| --------------- | ---------------------------------------- | -------------------------------------------- |
   >| **真实身份**    | Bash **语法层面的硬性保留字**            | 封装在 Bash 内部的 **C 语言函数**            |
   >| **代表成员**    | `[[`, `if`, `while`, `for`, `then`, `do` | `cd`, `exit`, `echo`, `read`, `type`, `pwd`  |
   >| **重定向行为**  | **可以改变**后续重定向的解析逻辑         | 必须遵守标准的重定向和参数切分规则           |
   >| **别名干扰**    | 别名（Alias）**绝对无法**覆盖关键字      | 别名可以覆盖内建命令（如 `alias cd='echo'`） |
   >| **段位/优先级** | **最高**（第一优先级）                   | **次高**（排在关键字和函数之后）             |

11.写一条命令，把文件复制为带当天日期的备份文件名（例如 `notes.txt` → `notes_2026-01-12.txt`）。（提示：`$(date +%Y-%m-%d)`）参见 [Command Substitution](https://www.gnu.org/software/bash/manual/html_node/Command-Substitution.html) 。

`cp notes.txt "notes_$(date +%Y-%m-%d).txt"` 的核心作用是：**利用 Linux 的“命令替换”机制，全自动将 `notes.txt` 复制并重命名为一个带有当前年月日标签的备份文件。**

为了彻底看清它的底层运作逻辑，我们可以将其拆解为以下三个核心维度：

------

1. 核心指令：`cp` 的标准操作

- **`cp`** 是外部命令 `copy` 的缩写，其标准语法为 `cp <源文件> <目标文件>`。
- 在这条命令中，第一个参数 `notes.txt` 是**源文件路径**，而第二个被双引号包裹的复杂长字符串则是生成的**目标备份文件名**。

2. 灵魂机制：`$(...)` 命令替换（Command Substitution）

当 Bash 解释器在命令行中看到 `$(...)` 符号时，它会启动一个最高优先级的**内部替换引擎**：

1. **开辟子 Shell**：Bash 会在后台开辟一个短暂的子进程，去执行括号内部的命令——这里执行的是 `date +%Y-%m-%d`。
2. **执行并格式化时间**：`date` 命令接收到 `+%Y-%m-%d` 参数后，会把当前的系统时间强行格式化输出。由于今天是 **2026年7月25日**，它在后台吐出的纯文本字符串就是 `2026-07-25`。
3. **原地抹去并替换**：子进程结束后，Bash 会把 `$(date +%Y-%m-%d)` 这一串符号从命令行中**物理抹去**，并把刚刚得到的文本 `2026-07-25` 丝滑地塞回原位。

在命令真正执行前，原本的整行命令在内存里已经被 Bash 彻底改写成了：

```bash
cp notes.txt "notes_2026-07-25.txt"
```

3. 安全防线：为什么外层必须加 `"双引号"`？

我们在之前讨论弱引用时提到过，双引号的作用是**防止词法分割（Word Splitting）**。

- 虽然当前的日期 `2026-07-25` 里面不包含空格，看似不加双引号也能运行。
- 但是在真正的自动化运维和项目中，如果未来的时间格式改成了包含空格的形式（例如带有小时和分钟：`2026-07-25 10:54`），不加双引号的命令展开后就会变成 `cp notes.txt notes_2026-07-25 10:54.txt`。
- 此时 `cp` 会认为你想把前两个文件复制到名为 `10:54.txt` 的**目录**里，从而直接抛出致命的 `target is not a directory` 报错。**加双引号筑起了最稳固的安全防线。**

12.修改讲义中的「复现偶尔才会失败的测试」脚本（flaky test），使它能够从命令行参数接收测试命令，而不是在脚本中写死 `cargo test my_test`。（提示：`$1` 或 `$@`）参见 [Special Parameters](https://www.gnu.org/software/bash/manual/html_node/Special-Parameters.html) 。

```bash

    echo "Usage: $0 <test_command>"

    exit 1
```

关键修改点共有以下 3 处：

1. 使用 `"$@"` 替换硬编码的 `cargo test my_test`

- **修改前**：测试命令死写在脚本内部。
- **修改后**：替换为特殊的 Bash 参数 **`"$@"`**。
- **原理**：`"$@"` 代表命令行传入的**所有参数**。当加上双引号包裹时，Bash 会保留每个参数的独立性和原始空格。这使得脚本极为通用，无论传入的是 `cargo test my_test` 还是带有复杂参数的 `pytest -v --maxfail=1`，都能被完整、原封不动地当作一条命令来执行。
- 将测试命令移入 `if` 条件结构中

- **修改前**：直接在 `while` 后面跟测试命令。
- **修改后**：改用 `while true; do if "$@"; then ... else break; fi; done` 结构。
- **原理**：因为脚本开启了 **`set -e`**（一旦命令出错立即崩溃退出）。在原脚本中，如果测试失败，脚本往往会直接闪退，导致循环后面的 `kill $STRESS_PID` 和日志打印逻辑根本无法执行（`stress` 进程会在后台常驻）。而将 `"$@"` 放入 **`if` 条件判断** 中，Bash 会认为这是一个“受保护的状态检查”，即使测试返回非 0 状态码也不会触发 `set -e` 闪退，从而确保了脚本能够优雅地跳出循环并完成善后清理。
- 引入 `$#` 参数个数安全检查

- **修改前**：脚本没有进行任何参数校验。
- **修改后**：在脚本头部增加了 `if [ $# -eq 0 ]; then ... exit 1; fi`。
- **原理**：脚本开启了 **`set -u`**（遇到未定义变量立即报错退出）。如果直接读取 `"$1"`，在用户忘记传参时会导致脚本由于 `set -u` 而直接报错闪退。使用 **`$#`**（参数总个数）进行 `[ $# -eq 0 ]` 的判断，是在极端严格模式下最安全、合规的参数校验方式，能拦截空参数并输出友好的用户提示。

>`$` 在 Bash 中的全景详细用法：
>
>一、 变量取值与扩展（Value Extraction）
>
>这是最基础的用法。在 Bash 中，赋值时不能加 `$`（如 `RUN=1`），但**读取、引用**变量值时必须加 `$`。
>
>1. 基础变量引用：`$var`
>
>- **语法**：`$变量名`
>- **示例**：`kill $STRESS_PID`
>- **逻辑**：把变量 `STRESS_PID` 中存储的数字（如 `4102`）取出来，传给 `kill` 命令。
>- 边界保护与安全求值：`${var}`
>
>- **语法**：用 `{}` 明确限定变量名的范围。
>- **示例**：`echo "Running ${RUN}st time."`
>- **为什么要用**：如果不加 `{}` 写成 `$RUNst`，Bash 会去寻找一个叫 `RUNst` 的变量。加了 `{}` 就能准确识别变量是 `RUN`。
>- **高级扩展（参数展开）**：`${1:-}`。表示如果第一个参数 `$1` 未定义，则返回空值（`:-` 后面的内容），这在开启了 `set -u` 的严格讲义脚本中可以防止程序闪退。
>
>------
>
>二、 命令行参数与系统特殊状态（Special Parameters）
>
>Bash 内置了一系列特殊的 `$+字符`，用来获取脚本执行时的上下文和系统状态。
>
>1. 批量参数：`$@` 与 `$*`（重点）
>
>- **`"$@"`（最推荐）**：代表所有参数，且**保留每个参数的独立性和空格**。在讲义脚本中，`while "$@"` 能把 `cargo test my_test` 完整执行，就是因为 `"$@"` 把它们分成了独立的单词处理。
>- **`"$\*"`**：把所有参数连成一个巨大的单一字符串（用空格隔开），无法直接作为带参数的命令执行。
>- 位置参数：`$0`, `$1`, `$2` ...
>
>- **`$0`**：脚本自身的名称（如 `./flaky_handler.sh`）。
>- **`$1`**：命令行传进来的第一个参数。如果命令是 `cargo test`，则 `$1` 是 `cargo`。
>- 状态与进程标识：`$?`, `$!`, `$$`
>
>- **`$?`**：**上一条命令的退出状态码**。`0` 代表成功，非 `0` 代表失败。`while` 循环和 `set -e` 严格模式的核心就是时刻监控 `$?` 的值。
>- **`$!`**：**最近一次在后台运行的进程 PID**。脚本中 `stress --cpu 8 &` 启动后，紧接着用 `STRESS_PID=$!` 成功抓到了它的进程号，以便最后执行 `kill`。
>- **`$#`**：传入参数的**总个数**。脚本中用 `[ $# -eq 0 ]` 检查用户有没有漏写测试命令。
>
>------
>
>三、 高级求值与结构扩展（Evaluation & Substitution）
>
>这类用法将 `$` 与括号结合，用于在脚本中动态执行代码或进行数学计算。
>
>1. 命令替换：`$(command)`
>
>- **语法**：执行括号内的命令，并把命令的**标准输出结果**替换到当前位置。
>- **脚本实例**：`LOGFILE="test_runs_$(date +%s).log"`
>- **逻辑**：先在后台悄悄执行 `date +%s` 拿到时间戳（如 `1711785600`），然后把这个数字填进去，最终拼接成文件名。
>- 算术扩展：`$((expression))`
>
>- **语法**：在双括号内进行**整数数学运算**，并把最终的计算结果取出来。
>- **示例**：`TOTAL=$((RUN + 1))`
>- **逻辑**：如果 `RUN` 是 `5`，括号内计算出 `6`，前面的 `$` 把 `6` 取出来赋值给 `TOTAL`。
>
>------
>
>四、 字符串修饰字面量（Literal Modifiers）
>
>这是 `$` 与引号紧密结合时的特异功能，彻底改变了引号内文本的解析规则。
>
>1. ANSI-C 转义解析：`$' '`
>
>- **语法**：`$'带有反斜杠的文本'`
>- **逻辑**：强迫 Bash 像 C 语言一样去解析里面的 `\n`（换行）、`\t`（制表符）、`\e`（ESC键）。
>- **示例**：`echo $'Error:\nTest failed!'` 会直接输出两行。
>- 国际化本地翻译：`$" "`
>
>- **语法**：`$"英文文本"`
>- **逻辑**：让 Bash 去系统语言包里寻找该英文的本地语言翻译（如中文）。如果找不到，则退化为普通双引号原样输出。
>
>在阅读或编写 Bash 脚本时，看到 `$` 可以直接套用以下公式：
>
>1. 后面是 **字母/大括号** (`$RUN`, `${RUN}`) \(\rightarrow \) **读变量值**
>2. 后面是 **数字/特殊符号** (`$1`, `$@`, `$!`, `$#`) \(\rightarrow \) **读参数或系统状态**
>3. 后面是 **小括号** (`$(...)`) \(\rightarrow \) **执行命令并拿走输出**
>4. 后面是 **双小括号** (`$((...))`) \(\rightarrow \) **计算数学题并拿走结果**
>5. 后面是 **带引号的字符串** (`$'...'`, `$"..."`) \(\rightarrow \) **启用高级转义或翻译功能**

13.使用管道找出你「home 目录」中最常见的 5 种文件扩展名。（提示：组合 `find` 、`grep` / `sed` / `awk`、`sort`、`uniq -c` 以及 `head`）

```bash
find ~ -type f -name "*.*" | awk -F. '{print $NF}' | sort | uniq -c | sort -rn | head -n 5
```

该命令通过管道（`|`）将上一条命令的输出作为下一条命令的输入，层层过滤和统计：

1. **`find ~ -type f -name "\*.\*"`**
   - 寻找 `home` 目录（`~`）下的所有普通文件（`-type f`）。
   - `-name "*.*"` 用于过滤掉没有扩展名的文件（如纯文本的 Makefile、隐藏的 `.bashrc` 或无后缀的可执行文件），确保后续切分不会出错。
2. **`awk -F. '{print $NF}'`**
   - 以点号（`.`）作为分隔符（`-F.`）切分文件名。
   - `$NF` 是 awk 的内置变量，代表最后一个字段。通过打印 `$NF`，可以完美提取出最末尾的扩展名（即使文件名里有多个点，如 `archive.tar.gz` 也会正确提取出 `gz`）。
3. **`sort`**
   - 对提取出来的所有扩展名进行排序。这是使用 `uniq` 命令前必不可少的步骤，因为 `uniq` 只能合并**相邻且相同**的行。
4. **`uniq -c`**
   - 去除重复的扩展名行，并在每行前面加上 `-c`（count）参数，输出该扩展名出现的**总次数**（例如：`1423 txt`）。
5. **`sort -rn`**
   - 再次进行排序。`-n` 代表按数字大小（次数）排序，`-r` 代表逆序（降序）。这样可以把出现次数最多的扩展名排在最前面。
6. **`head -n 5`**
   - 截取前 5 行，即最终输出出现频次最高的 5 种文件扩展名及其数量。

>**`find` 是 Linux/Unix 系统中最强大、最常用的文件搜寻工具。**它不仅能通过文件名查找，还能根据文件的**大小、类型、权限、修改时间、所属用户**等全方位属性进行精准匹配，并对搜索结果直接执行后续操作。

>以下为你详细拆解 `find` 命令的语法、核心匹配条件、高级逻辑组合以及操作执行。
>
>------
>
>一、 核心语法结构
>
>```bash
>find [搜索路径] [匹配条件表达式] [后续操作]
>```
>
>- **搜索路径**：可以是一个或多个目录。省略时默认为当前目录（`.`）。
>- **匹配条件**：可以有多个，默认它们之间是“并且（AND）”的关系。
>- **后续操作**：对找到的文件进行处理（如删除、复制、统计）。省略时默认为打印到屏幕（`-print`）。
>
>------
>

>
>1. 按文件名搜索：`-name` / `-iname`

>- `-iname "pattern"`：**忽略大小写**（*i* 代表 *ignore case*）。

>

>- `-type d`：目录/文件夹 (Directory)

>

>```
>
>3. 按文件大小搜索：`-size`
>
>- 支持单位：`k` (KB), `M` (MB), `G` (GB)。
>- 符号前缀：`+`（大于）、`-`（小于）、无前缀（刚好等于）。
>
>```bash
>find / -size +1G                  # 查找全盘大于 1GB 的巨型文件
>find . -size -10k                 # 查找当前目录下小于 10KB 的小文件
>```
>
>4. 按时间属性搜索：`-mtime` / `-atime` / `-ctime`
>
>- `-mtime`：修改时间 (Modify time，文件内容被修改)。
>- `-atime`：访问时间 (Access time，文件被读取或执行)。
>- 单位是**天**（如果是按**分钟**计算，使用 `-mmin`, `-amin`）。
>- 前缀：`+7`（7天前）、`-7`（7天内）。
>
>```bash
>find /tmp -mtime -1               # 查找过去 24 小时内被修改过的临时文件
>find . -mmin +60                  # 查找 1 小时前（大于60分钟）修改过的文件
>```
>
>5. 按权限与归属搜索：`-perm` / `-user` / `-group`
>
>- `-user username`：属于某个用户。
>- `-perm 755`：权限严格等于 755。
>
>```bash
>find /home -user alice -type f    # 查找属于用户 alice 的所有普通文件
>```

>1. **与（AND）**：`-a`（默认，写多个条件时不加参数就是 AND）。
>2. **或（OR）**：`-o`（只要满足其中一个条件即可）。
>3. **非（NOT）**：`!` 或 `-not`（取反，排除某些情况）。
>
>```bash

>```

>
>四、 后续操作（找到文件后怎么处理）
>
>1. 默认打印：`-print` / `-print0`
>
>- `-print`：默认行为，每个结果后面加换行符。
>- `-print0`：每个结果后面加空字符 `\0`，专门用来配合 `xargs -0` 解决文件名包含空格的问题。
>- 安全删除：`-delete`
>
>直接在文件系统中物理删除找到的文件。**（使用前务必先去掉 `-delete` 预览一遍结果，防止误删！）**
>
>```bash
>find . -name "*.tmp" -delete     # 删除当前目录下所有的临时 .tmp 文件
>```
>
>3. 内置执行：`-exec`
>
>对找到的每一个文件，原地执行一条指定的 shell 命令。
>
>- **语法固定格式**：`-exec 命令 {} \;`
>- `{}` 是占位符，代表当前找到的文件名。
>- `\;` 是结束符，告诉 `find` 命令到这里结束（反斜杠用于转义分号）。
>
>```bash
># 查找所有的 .conf 配置文件，并直接复制到 /backup 目录下
>find /etc -name "*.conf" -exec cp {} /backup/ \;
>```
>
>*注：正如前一题所讨论的，`-exec` 会为每个文件启动一个新进程，效率较低；大批量处理文件时，更推荐结合 `xargs` 使用。*
>

使用 `find` 和 `xargs` 结合并正确处理文件名中空格的命令如下：

```bash
find . -type f -name "*.sh" -print0 | xargs -0 wc -l
```

管道命令逐段解析

1. **`find . -type f -name "\*.sh" -print0`**
   - `.`：从当前目录开始向下查找。
   - `-type f`：只查找普通文件。
   - `-name "*.sh"`：匹配所有以 `.sh` 结尾的文件。
   - **`-print0`（加分项关键点）**：这是处理空格的核心。默认情况下，`find` 输出的文件名之间用换行符（`\n`）分隔。如果文件名本身包含空格（例如 `my script.sh`），后续命令会误把它拆成 `my` 和 `script.sh` 两个文件。`-print0` 告诉 `find` 使用 **空字符（Null Character，即 `\0`）** 作为每个文件名之间的分隔符。
2. **`xargs -0 wc -l`**
   - **`-0`（加分项关键点）**：告诉 `xargs` 输入的特殊数据是用 **空字符 `\0`** 分隔的，而不是默认的空格或换行。这样 `xargs` 就能精准识别出带有空格的完整文件名，并安全地转换为参数。
   - `wc -l`：统计并输出每个文件的行数，并在最后一行自动输出所有文件的总行数（total）。

------

**为什么不用 `find -exec`，而推荐使用 `xargs`？**

题目特意要求“不要用 `find -exec`”，这是因为 `xargs` 具备极高的性能优势：

- **`find -exec wc -l {} \;` 的缺点**：每找到一个 `.sh` 文件，系统就会**创建并启动一个全新的 `wc` 进程**。如果有 1000 个文件，就会启动 1000 次进程，效率极低且消耗系统资源。
- **`xargs` 的优势**：它会把 `find` 找到的数千个文件名打包成一大组，**只启动一次（或极少数次）`wc` 进程**，把所有文件名一次性传给 `wc`（形如 `wc -l file1.sh file2.sh ...`），性能提升数十倍。

```bash

```

1. `curl -s https://missing.csail.mit.edu/`

- **做什么**：从指定的 URL 下载网页的 HTML 源码，并将源码作为纯文本直接吐给下一个命令。
- **核心参数 `-s` (Silent)**：
  - **作用**：关闭 `curl` 默认输出的下载进度条、下载速度等统计信息。
  - **为什么关键**：如果不加 `-s`，进度条信息会被一同传进管道中，从而严重干扰后面 `grep` 的匹配和 `wc` 的计数，导致结果不准。

------

2. `grep -E "[0-9]+/[0-9]+/[0-9]+"`

- **做什么**：从大段的 HTML 源码中，只把符合“日期格式”特征的行过滤并筛选出来。
- **核心参数 `-E` (Extended Regular Expressions)**：
  - **作用**：启用扩展正则表达式。只有加了 `-E`，Bash 才能正确识别 `+`（代表前面的字符匹配 1 次或多次）等高级正则元字符。
- **正则表达式 `[0-9]+/[0-9]+/[0-9]+` 解析**：
  - `[0-9]+`：匹配一个或多个连续的数字（代表月份）。
  - `/`：匹配字面上的斜杠字符。
  - `[0-9]+`：再次匹配一个或多个连续的数字（代表日期）。
  - `/`：第二个斜杠。
  - `[0-9]+`：第三次匹配一个或多个连续的数字（代表年份）。
  - **整体效果**：它能精准捕捉到 HTML 源码里所有的日期文本。例如网站底层的 `<li><strong>1/12/26</strong>: ...</li>` 行，就会因为包含了 `1/12/26` 而成功通过筛选。所有不包含该日期格式的行（如课程介绍、翻译列表、页脚等）则会被全部丢弃。

3. `wc -l`

- **做什么**：对前面被 `grep` 筛选出来的行进行最终计数。
- **核心参数 `-l` (Lines)**：
  - **作用**：告诉 `wc`（Word Count）工具，**只统计行数**，不需要统计字数或字符数。
  - **整体效果**：由于每一讲课程在页面大纲中都独占一行，因此有多少个匹配的日期行，输出的就是多少个数字（在你的环境中输出的就是 `19`）。

17.`awk` 可以按列值过滤行并改写输出。例如，`awk '$3 ~ /pattern/ {$4=""; print}'` 会只输出第三列匹配 `pattern` 的行，并省略第四列。请写一个 `awk` 命令：只输出第二列大于 100 的行，并交换第一列和第三列。可用这条命令测试：`printf 'a 50 x\nb 150 y\nc 200 z\n'`

```bash
pei15@HONORFuture:~$ printf 'a 50 x\nb 150 y\nc 200 z\n' | awk '$2 > 100 {print $3, $2, $1}'
y b
z c
```

`awk` 命令逐段详细解析

- **`$2 > 100`**：这是 **条件动作器（Condition）**。`awk` 默认以空格或制表符切分列。`$2` 代表第二列的值。该条件会检查每一行，只有当第二列的数字严格大于 100 时（例如 `150` 和 `200` 所在的行），才会触发后面花括号内的动作。第一行 `50` 所在的行则会被直接过滤丢弃。
- **`{print $3, $2, $1}`**：这是 **执行动作（Action）**。
  - `$3` 代表第三列的值，`$1` 代表第一列的值。
  - 通过将 `$3` 写在前面，`$1` 写在后面，直接实现了**交换两列输出**的目的。
  - *注*：中间的**逗号 `,`** 非常关键，它告诉 `awk` 在输出这两个变量时，自动使用系统的默认输出字段分隔符（OFS，默认为一个空格）将它们隔开。

第一部分：拆解讲义中的 SSH 日志处理管道

讲义中用于分析远程服务器安全日志、提取高频异常登录用户名的完整管道命令如下：

```bash
ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \

  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd, -
```

该管道通过以下 10 个步骤处理数据：

1. **`ssh`**：远程连接并执行后续命令。
2. **`journalctl -u sshd -b-1`**：获取上次 SSH 服务的相关日志。
3. **`grep "Disconnected from"`**：筛选出断开连接的日志条目。
4. **`sed -E ...`**：通过正则表达式从日志中提取出用户名。
5. **`sort`**：将用户名按字典顺序排序。
6. **`uniq -c`**：统计每个用户名出现的次数。
7. **`sort -nk1,1`**：按用户名出现的次数（数字）进行升序排序。
8. **`tail -n10`**：选取最后 10 行，即高频登录的前 10 个用户。
9. **`awk '{print $2}'`**：仅打印用户名，去除次数。
10. **`paste -sd, -`**：将纵向排列的用户名合并为逗号分隔的单行文本。
