# 智能体编程
## 概述
### 编程智能体 = 带工具访问的对话式 AI：读写文件 / 搜索网页 / 执行 Shell
### 运行形态：IDE 内嵌 / 独立 CLI / GUI
### 演示：把代码改写为 argparse CLI + 类型注解 + 通过类型检查
### 心智模型：管理实习生（干繁琐活，需指导，偶尔纠正）
### 支持多轮交互、可中断、可文字反馈纠偏
## AI 模型与智能体的工作原理
### LLM = 对提示字符串的补全概率分布建模
### 推理 = 从概率分布采样
### 上下文窗口：输入 + 输出的最大长度
### 多轮交互：每次新提示把整个对话历史作为输入
### 工具调用：LLM 输出 → 工具调用请求 → 结果反馈 → 再次推理
### 核心概念约 200 行代码可实现
### 隐私
#### 默认大量数据发送云端（代码库副本 + 交互记录）
#### 开源工具/LLM 已有但不及专有模型
#### 本地运行前沿开源 LLM 受硬件限制，尚不现实
## 应用场景
### 实现新功能：规范描述是艺术；TDD 特别有效
### 修复错误：进入反馈循环最有效（让模型直接运行失败检查）
### 重构代码：重命名方法 → 拆分到独立模块
### 代码审查：“审查未提交更改” / “审查 PR {链接}”
### 理解代码：新成员入职提问
### 作为 Shell 使用：自然语言调用命令（find / mogrify 示例）
### 氛围编程（Vibe coding）：不写一行代码实现应用
## 高级智能体
### 可复用提示词：模板化；部分工具已弃用、由 Skills 取代
### 并行智能体
#### 同一任务多次运行取最佳（LLM 有随机性）
#### 不同任务并行（互不重叠的功能）
#### git worktrees 防止改动互相干扰
### MCP（Model Context Protocol）
#### 开放协议：把编程智能体与工具连接
#### 示例：Notion MCP 读文档 → 起草计划 → 实现原型
#### 发现目录：Pulse / Glama
### 上下文管理
#### 清空上下文窗口：开始新对话
#### 回退对话：撤销历史中的步骤
#### 压缩（Compaction）：自动总结前半段对话
#### llms.txt：供 LLM 推理的高信息密度文档标准
#### AGENTS.md：启动时预填充全部内容（Claude Code /init 自动生成）
#### Skills：按需加载，避免上下文膨胀
#### 子智能体：隔离上下文，顶层不被子任务内容膨胀
### 用 LLM 生成 Skills / 子智能体（Claude Code /agents 示例）
## 注意事项
### LLM 是概率性预测而非真智能 → 审查正确性与安全性
### 验证代码有时比自己写更难 → 关键代码手动编写
### 可能钻牛角尖 / 调试死循环
### 不当拐杖：警惕过度依赖、理解浮于表面
### 仍有大量任务 AI 无法完成，计算思维有价值
## 推荐软件
### Claude Code（Anthropic）
### Codex（OpenAI）
### opencode（开源）

### 3. 从零氛围编程一个小应用（不手写一行代码）

### 5. 用智能体完成 regex 替换练习，思考直接编辑文件的缺点与替代方案
