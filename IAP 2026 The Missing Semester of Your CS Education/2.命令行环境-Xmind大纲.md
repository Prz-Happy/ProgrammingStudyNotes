# 命令行环境 — Xmind 大纲

> 基于 MIT 2026 IAP《The Missing Semester of Your CS Education》Command-line Environment 章节

## 1. 核心概念总览
- Shell 脚本与普通编程语言的关键差异：输入/输出不如函数签名那样显式可见
- 五大核心机制
    - 参数（Arguments）
    - 流（Streams）
    - 环境变量（Environment Variables）
    - 返回码（Return Codes）
    - 信号（Signals）

## 2. 参数
- 本质：纯字符串列表，由程序自行解析
- 位置参数
    - `$1` ~ `$9` — 第 1 到第 9 个参数
    - `$0` — 程序本身名称
    - `$@` — 所有参数（列表形式，保持独立性）
    - `$#` — 参数个数
- 选项约定（非语言强制，社区惯例）
    - 单横线 `-a` — 单字母选项，可合并 `-la` = `-l -a`
    - 双横线 `--all` — 长名称选项
    - 顺序无关：`ls -la` = `ls -al`
    - 常见通用选项：`--help` / `--verbose` / `--version`
- 不定数量参数语法糖
    - `mkdir src docs` 等价于两次单独调用
    - 真正威力来自配合通配符
- 通配符扩展（Globbing）— Shell 在调用程序前展开
    - `*` — 匹配零个或多个任意字符
    - `?` — 恰好匹配一个字符
    - `{}` — 花括号展开，逗号分隔 → 多个参数
        - `folder/{a,b,c}.py` → `folder/a.py folder/b.py folder/c.py`
        - `image.{png,jpg}` → `image.png image.jpg`
        - `*{.py,.sh}` — 组合技巧，移动所有 .py 和 .sh 文件
    - zsh 增强：`**` 递归匹配
- 典型用例：`rm *.py`（Shell 先展开，rm 收到的是具体文件名，不是通配符字符串）

## 3. 流
- 管道 `|`：前后程序同时启动，边产生边消费，非串行等待
    - 演示并发性：管道中除被阻塞的进程外，其余立即运行
- 三条标准流
    - `0` stdin — 标准输入（默认键盘）
    - `1` stdout — 标准输出（默认屏幕，管道的传递对象）
    - `2` stderr — 标准错误（默认屏幕，独立于 stdout，不被管道传递）
- `-` 作为文件名：表示从 stdin 读取
- 重定向语法
    - `> file` — stdout 覆盖写入文件
    - `>> file` — stdout 追加写入文件
    - `2> file` — stderr 重定向到文件
    - `&> file` — stdout + stderr 合并重定向
    - `< file` — 从文件重定向 stdin
    - `> /dev/null 2>&1` — 丢弃所有输出
- 模糊查找器 `fzf`
    - 从 stdin 逐行读取，交互式筛选
    - 典型用法：`ls | fzf` / `cat ~/.bash_history | fzf`

## 4. 环境变量
- 赋值语法：`foo=bar`（等号两边不能有空格！）
    - `foo = bar` 会被解析为"调用程序 foo，参数 `=` 和 `bar`"
- 变量无类型，本质全是字符串
- 引号差异
    - `'单引号'` — 字面量，不展开变量，不处理转义
    - `"双引号"` — 展开变量 `$var`，处理转义序列
- 命令替换 `$(command)`
    - `files=$(ls)` — 把命令 stdout 存入变量（保留换行符）
- 进程替换 `<()`
    - `<(CMD)` 执行 CMD，输出写入临时文件，用文件名替换
    - 适用场景：命令要求文件而非 stdin，如 `diff <(ls src) <(ls docs)`
- 环境变量传递机制
    - Shell 调用子程序时自动传递一组环境变量
    - `printenv` 查看当前所有环境变量
    - 约定：全大写命名（`HOME` / `PATH` / `DEBUG`）
- 三种设置方式
    - 行内临时设置：`TZ=Asia/Tokyo date`（仅该命令生效，当前 Shell 不变）
    - `export VAR=value` — 修改当前 Shell 环境，所有子进程继承
    - `unset VAR` — 删除变量
- 隐式行为修改：程序通过读环境变量改变行为，无需显式传参（如 `$HOME` / `$TZ`）

## 5. 返回码
- 约定：`0` = 成功，非 `0` = 出错
- `$?` — 获取上一条命令的返回码
- `exit NUM` — 主动返回退出码
- 短路布尔运算符（基于返回码判断）
    - `cmd1 && cmd2` — cmd1 成功(0) 才执行 cmd2
    - `cmd1 || cmd2` — cmd1 失败(非0) 才执行 cmd2
    - `true` — 永远返回 0 的内建命令
    - `false` — 永远返回非 0 的内建命令
- 控制流同样基于返回码
    - `if grep -q "pattern" file.txt; then ...; fi`
    - `while read line; do ...; done < file.txt`

## 6. 信号
- 本质：软件中断（Software Interrupt）
- 信号处理流程
    - 进程收到信号 → 暂停当前执行 → 处理信号 → 决定后续行为
- 常用信号与触发方式
    - `SIGINT` — `Ctrl-C`，打断进程（可被捕获/忽略）
    - `SIGQUIT` — `Ctrl-\`，备选终止方式
    - `SIGTERM` — `kill -TERM <PID>`，请求优雅退出
    - `SIGSTOP` — 暂停进程（不可捕获）
    - `SIGTSTP` — `Ctrl-Z`，终端暂停（Terminal Stop）
    - `SIGKILL` — 强制立即终止（不可捕获，可能留孤儿进程）
    - `SIGHUP` — 终端关闭时发送（Hangup）
- 作业控制
    - `Ctrl-Z` → 暂停前台任务
    - `fg` — 恢复到前台继续运行
    - `bg` — 恢复到后台继续运行
    - `jobs` — 列出当前终端会话未结束的作业
    - `%N` — 用作业号引用（如 `kill %1`）
    - `$!` — 最近放入后台的进程 PID
- 后台运行
    - `cmd &` — 命令末尾加 `&`，后台运行，立即归还提示符
    - 后台进程仍是终端子进程 → 关终端会收到 `SIGHUP` 被杀
- 防终端关闭
    - `nohup cmd &` — 忽略 `SIGHUP` 的包装命令
    - `disown` — 已启动进程脱离终端
    - 更佳方案：终端复用器（tmux）
- Shell 脚本中的信号处理
    - `trap cleanup EXIT` — 脚本退出时执行清理
    - `trap cleanup SIGINT SIGTERM` — 收到指定信号时执行

## 7. 远程机器（SSH）
- 基本连接：`ssh user@server`
- 非交互式执行命令
    - `ssh alice@server ls | wc -l` — ls 远程执行，wc 本地执行
    - `ssh alice@server 'ls | wc -l'` — 全部远程执行
- 推荐替代品：`mosh`（更好处理断线/休眠/高延迟）
- SSH 密钥认证
    - 比密码更安全、更方便
    - 生成密钥：`ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519`
    - 私钥 = 等同于密码，绝不泄露
- 复制公钥到服务器
    - `ssh-copy-id -i .ssh/id_ed25519 alice@remote`
    - 或手动：`cat .ssh/id_ed25519.pub | ssh alice@remote 'cat >> ~/.ssh/authorized_keys'`
- 文件传输
    - `scp` — 传统工具：`scp local_file remote_host:path/to/remote_file`
    - `rsync` — 增强版：检测重复跳过、符号链接/权限控制、断点续传 `--partial`
- SSH 配置文件 `~/.ssh/config`
    - 主机别名 + 默认参数（ssh/scp/rsync/mosh 均可复用）
    - 支持通配符：`Host *.mit.edu`

## 8. 终端复用器（tmux）
- 核心能力
    - 窗格（Pane）+ 标签页（Window）复用终端窗口
    - 分离（Detach）/ 附着（Attach）会话
    - 远程机器上尤其方便，基本替代 `nohup`
- 快捷键基础：`<C-b> x` = Ctrl+b 松开后再按 x
- 三级对象层级
    - **Sessions（会话）**：独立工作区，可包含多个 Window
        - `tmux` / `tmux new -s NAME` — 新建会话
        - `tmux ls` — 列出所有会话
        - `<C-b> d` — 分离当前会话
        - `tmux a` — 附着最近会话（`-t` 指定名称）
    - **Windows（窗口）**：同 Session 内的标签页
        - `<C-b> c` — 新建窗口
        - `<C-b> N` — 跳到第 N 个窗口
        - `<C-b> p` / `<C-b> n` — 前/后窗口
        - `<C-b> ,` — 重命名窗口
        - `<C-b> w` — 列出所有窗口
    - **Panes（窗格）**：同窗口内的分屏
        - `<C-b> "` — 水平拆分
        - `<C-b> %` — 垂直拆分
        - `<C-b> <方向键>` — 切换到指定方向窗格
        - `<C-b> z` — 缩放切换
        - `<C-b> [` — 滚动回看模式（Space 开始选择，Enter 复制）
        - `<C-b> <space>` — 轮换布局

## 9. 定制 Shell（Dotfiles）
- Dotfiles = 以 `.` 开头的纯文本配置文件（`ls` 默认隐藏）
- 常用工具的配置文件
    - `bash` — `~/.bashrc` / `~/.bash_profile`
    - `git` — `~/.gitconfig`
    - `vim` — `~/.vimrc` + `~/.vim/`
    - `ssh` — `~/.ssh/config`
    - `tmux` — `~/.tmux.conf`
- PATH 扩展
    - `export PATH="$PATH:path/to/append"`
- 包管理器（安装新 CLI 工具）
    - macOS: Homebrew — `brew install ripgrep fd`
    - Ubuntu/Debian: `apt`
    - Fedora: `dnf`
    - Arch: `pacman`
- 推荐现代 CLI 工具
    - `ripgrep`(rg) — 更快的 grep，默认更合理
    - `fd` — 更快的 find，更易用
    - `tldr` — 简化版示例驱动的 man page
    - `command-not-found.com` — 查命令在各发行版如何安装
- ⚠️ `curl | bash` 风险
    - 先下载 → 检查 → 再执行
    - 步骤：`curl -o install.sh <url>` → `less install.sh` → `bash install.sh`
- Alias（别名）
    - 语法：`alias alias_name="command_to_alias arg1 arg2"`（等号两边不能有空格）
    - 实用示例
        - `alias ll="ls -lh"` — 常用选项简写
        - `alias gs="git status"` / `alias gc="git commit"` — 节省输入
        - `alias mv="mv -i"` / `alias mkdir="mkdir -p"` — 覆盖默认行为
        - `alias sl=ls` — 防止手误
    - `\ls` — 临时绕过别名
    - `unalias la` — 删除别名
- Alias 的局限：不能在命令中间接收参数 → 复杂行为改用 Shell Function
- 反向历史搜索：`Ctrl-R`（配合 fzf 集成可升级为交互式模糊搜索）
- Dotfiles 管理最佳实践
    - 放入独立目录 + 版本控制（Git）
    - 用符号链接部署到实际位置
    - 好处：快速安装 / 可移植 / 同步方便 / 变更可追踪
- Shell 框架与插件
    - 通用框架：`prezto` / `oh-my-zsh`
    - 推荐插件：zsh-syntax-highlighting / zsh-autosuggestions / zsh-completions / powerlevel10k
    - 忠告：不必用大而全框架，单独安装所需插件更快更轻（大框架可能拖慢启动）
    - 替代方案：`fish` shell 默认内置很多此类功能

## 10. Shell 中的 AI
- 命令生成：`llm cmd "用自然语言描述需求"` → 输出对应命令
- 管道集成：LLM 作为管道一环处理非结构化文本
    - 场景：从格式不一致的文本中提取信息（正则难处理的场合）
    - 用法：`INSTRUCTIONS="..."` → `llm "$INSTRUCTIONS" < input.txt`
- AI Shell（元 Shell）
    - Claude Code 等工具：接收英文指令 → 转换为 Shell 操作/文件编辑/多步骤任务

## 11. 终端模拟器
- 定义：提供 Shell 运行界面的图形程序
- 值得投入时间挑选（你会在终端里花几百上千小时）
- 常见可调维度
    - 字体选择
    - 配色方案
    - 键盘快捷键
    - 标签页 / 分栏支持
    - 回滚缓冲区配置
    - 性能（GPU 加速终端：Alacritty / Ghostty）

## 12. 推荐工具汇总
- `fzf` — 交互式模糊查找器，配合 stdin 使用
- `mosh` — SSH 替代品，抗断线/高延迟
- `tmux` — 终端复用器，会话分离/窗格/标签页
- `ripgrep`(rg) — 更快更合理的 grep
- `fd` — 更快更易用的 find
- `tldr` — 示例驱动的简化 man page
- `shellcheck` — Shell 脚本静态检查
- `llm`(simonw/llm) — 命令行 LLM 工具
- Claude Code — AI 元 Shell，英文指令→Shell 操作
- `Alacritty` / `Ghostty` — GPU 加速现代终端模拟器
